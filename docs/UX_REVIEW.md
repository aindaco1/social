# Social UX review and Mixpost comparison

Reviewed: 2026-09-05. Baseline: installed 0.1.9 and source at `0d9bbe9`; the improvements below are included in the 0.1.10 release preparation. Historical candidate observations do not imply broader acceptance; current publication status is in [the launch plan](MVP_LAUNCH_PLAN.md).

Latest Local AI follow-through (2026-09-06): the upscaler now uses bundled native LiteRT CPU with automatic older-macOS Wasm compatibility, not a loopback-hosting workaround. Implementation, user instructions, measured app acceptance and the now-notarized isolated candidate are recorded in [Local AI](LOCAL_AI.md#packaged-app-acceptance) and its linked evidence. Earlier isolation experiments and the resolved clock blocker below remain historical evidence, not the active implementation plan.

## Verdict

The app has the intended local-first publishing foundation, but feature presence is ahead of end-to-end acceptance. The follow-up implementation below addresses the draft, calendar/time, missing-data, and workflow-density findings locally. It is not yet reasonable to say that every intended outcome has been met: live provider, signed-release, full accessibility, recovery, and packaged AI acceptance remain separate gates.

The Dust Wave visual identity can stay. Mixpost's useful lessons are about clear entry points, focused composition, nearby previews, explicit saving state, and revealing advanced controls only when needed—not copying every feature of its hosted/team product.

## Initial prioritized findings

These are the baseline reproductions and recommendations, retained as audit evidence. The follow-up section below records implemented corrections; [USER_FLOWS.md](USER_FLOWS.md) is the current status inventory.

### P1 — Protect unsaved work at every composer replacement entry

**Reproduction:** write an unsaved post, leave for Calendar, choose New Post. The composer opens empty with a prefilled time; no confirmation appears. The isolated test draft was recoverable after a normal restart before this shortcut, proving that ordinary persistence does not protect this transition.

`createPostFromCalendarDate`, `createPostFromCalendarSlot`, and other content-replacement paths call `resetDraftEditor`; the calendar paths are in `resources/desktop/src/App.vue`. The global Continue draft added here does not reset it.

**Next change:** one shared replacement guard with Keep editing, Save draft and continue, and Discard choices. Reuse the existing confirmation infrastructure and draft persistence. Apply it to calendar, media-to-post, and existing-post editing; do not implement separate prompts in each view. Test cancellation, save failure, replacement, relaunch, and account-specific/media-only drafts.

### P1 — Use one calendar window contract

The frontend month grid is 42 days aligned to the configured first weekday. Rust `calendar_window` currently queries the month's first day minus ten days through its last day plus ten days. In September 2026, the UI includes October 11 but the query ends October 10. A post on that visible final day can be absent from the query.

**Next change:** derive both query and display from the same explicit start/end contract. Cover every month-start weekday, February/leap years, both week starts, year rollover, and posts on the first/last visible cells. Also replace nested calendar button semantics with separate date and post targets.

### P1 — Make time and date settings truthful and consistent

Settings exposes timezone and date-format choices. Scheduling parses a native `datetime-local` value with `new Date(...)`, using the Mac timezone; relevant formatters do not consistently consume the chosen timezone/date format. Time format and week start are used in some places, so this is not simply an unsaved-settings defect.

**Next change:** decide and document one workspace-timezone contract, then reuse one parse/format boundary across composer, calendar, post library, detail, and analytics. Test DST gaps/overlaps and users scheduling for a different zone. Do not silently reinterpret existing scheduled UTC instants. Until then, the new composer Mac-time label is the truthful behavior. Replace today's already-past 09:00 shortcut with a future time or an explicit choice.

### P1 — Preserve unknown analytics as unknown

Rust audience reports preserve missing observations as `None`. `AudienceLineChart.vue` currently coerces points through `Number(value) || 0`; provider summary cards also default absent metrics to zero. Consequently, no measurement and a genuine measured zero can look identical. A quiet zero-filled report is not proof of successful imports.

**Next change:** retain null points through charting, show Not imported / No data / Last updated where appropriate, and expose a contextual refresh/import action. Share this presentation between Dashboard and Analytics. Test legitimate zero, missing day, partial provider scopes, stale import, and failed import independently.

### P2 — Make composing the smallest useful workspace

Mixpost's retained `resources/js/Pages/Posts/CreateEdit.vue` shows explicit Saved/Error state and debounced saving; its current gallery keeps preview beside writing. Social already has a valuable sticky action bar and reusable provider preview cards, but puts preview after a long stack of setup sections.

**Next change:** retain the current editor, account-version model, validation, and preview components. Use compact account chips, hide version controls until needed, combine repeated Original/Base copy labels, and put preview beside the editor when width permits (a Preview tab otherwise). Keep Save/Schedule/Post now visible. Add truthful Saving / Recovered draft / Saved feedback backed by the actual persistence result, not a cosmetic timer.

### P2 — Separate ordinary account connection from operator setup

The shared provider catalog and provider-first modal are strong foundations. Six configured services do not mean six live-working integrations; four connected account records do not prove refresh, upload, or publication acceptance.

**Next change:** lead with Connect account; keep developer portals, intake CSV, setup packets, batch queues, raw scopes, and diagnostics behind relevant secondary controls. Distinguish Configured, Connected, and Verified in wording. Prefer the existing one-time Instagram pairing and shared setup packet seams; keep credentials in Keychain and out of guides. Continue provider-specific acceptance using personal test accounts when this evaluation is complete.

### P2 — Simplify media intake and finishing

Lead with Import files and drag/drop. Put URL import and path entry behind secondary choices, and internal MIME/storage/conversion information inside Details. Rename Clean to describe the actual orphan-cleanup effect. Preserve Unsplash attribution and Klipy attach-only restrictions; those are behavior, not clutter to remove.

### P2 — Finish the accessibility and viewport acceptance matrix

Execute full keyboard and VoiceOver flows, including nested dialogs, emoji/media pickers, calendar post activation, errors, and dynamic announcements. Test long accounts/labels and dense posts in both themes at minimum and wide supported native windows. The launch plan asks for 1024px QA while Tauri's minimum window is 1100px; reconcile that explicit support boundary. Token contrast tests do not prove every composite/hover/disabled state or screen-reader experience.

### P3 — Reduce repetition and keep maintenance simple

Calendar repeats the title and explanatory sentence; several screens repeat section titles. Prefer one page heading and one focused toolbar. `App.vue` is still a very large cross-workflow owner and the stylesheet retains historical override layers. Extract by existing responsibility only as a workflow changes; do not start a parallel design system or a large rewrite to obtain dark mode.

### Isolation diagnosis — 2026-09-06

A minimal public-API WKWebView test reproduced the failure independently of Social/Tauri/LiteRT. The exact LiteRT-style failure is the hidden `SharedArrayBuffer` constructor, not lack of Wasm atomics support. Raw evidence and the diagnostic reproducer remain in the local-only `artifacts/isolation-2026-09-06/` archive. The selected native implementation and current acceptance boundary are maintained in [Local AI](LOCAL_AI.md).

Native execution is not proven necessary; assess a narrowly scoped loopback Labs prototype and its security implications before choosing the next implementation. Do not weaken CSP or enable private WebKit flags.
